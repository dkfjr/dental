# Architecture — Dental VLA teleop pipeline

## Dataflow

`config/dataflow-mujoco.yaml` is a dora-rs dataflow. Each node is a separate
process; edges are typed streams.

```
 dora/timer/millis/2
        │ tick
        ▼
 quittable-tick-leader ──tick──┬─────────────┐
                               ▼             ▼
   Meta Quest 3 ──UDP:5006──▶ udp-receiver ─▶ ik ──▶ mujoco-viewer  (dental scene, --xml)
                               │ pose_left/right     position_left/right │
                               └──────── pose_left/right, joystick ──────┘
```

| node | source | role |
|------|--------|------|
| `quittable-tick-leader` | `enactic/dora-openarm-quitter` | 500 Hz master clock + clean-quit |
| `udp-receiver` | `enactic/dora-openarm-vr` (`dora-openarm-quest-receiver`) | parse Quest UDP JSON, LH→RH transform, One-Euro smoothing, trigger→gripper mapping; emits 7D poses in the `arm_origin` frame |
| `ik` | `enactic/dora-openarm-kinematics` (`dora-openarm-ik`) | bimanual Levenberg-Marquardt IK: pose targets → joint angles |
| `mujoco-viewer` | `enactic/dora-openarm-mujoco` | load scene via `--xml`, drive position actuators, render |

Only the **`--xml` argument of the mujoco node** differs from the stock
`dora-openarm-vr` MuJoCo dataflow. Everything upstream is reused unchanged, so
the existing Quest 3 teleop APK works against the dental scene as-is.

## Frames & coordinate conventions

- **Teleop reference frame = the `arm_origin` site** in the scene (chest level,
  between the arms, world z=0.698). The receiver expresses controller poses
  relative to this site, and the IK node interprets targets in the same frame.
  The dental scene inherits `arm_origin` from the OpenArm bimanual model — do
  not rename or remove it.
- **Unity (left-handed) → MuJoCo/OpenArm (right-handed)**, done in the receiver:
  - position: `p_mujoco = [x, y, -z]`
  - quaternion: `q_mujoco = [qw, -qx, -qy, qz]` (stored scalar-first `wxyz`)
  - a saved **reference pose** (`rf`) is subtracted so motion is relative to
    where the operator was standing (NECK mode), then mapped into the robot
    workspace by a fixed frame rotation + offset (`FRAME_OFFSET_NECK`).
- **Trigger → gripper**: index trigger `0..1` maps to a calibrated gripper angle
  (right: −45°→+10°, left: +45°→−10°).

## Pose packet (Quest → PC, UDP JSON)

```
t                       headset timestamp (s)
lc / rc / rf            left ctrl / right ctrl / reference  {x,y,z,qx,qy,qz,qw}
lt / rt                 triggers            0..1
lg / rg                 grips               0..1
lsx lsy rsx rsy         thumbsticks         -1..1
a b x y                 buttons             bool
v vl vr                 validity            0=OK 1=STALE 2=INVALID
```

`src/dental_vla/mock_quest_sender.py` emits exactly this schema so the pipeline
runs without a headset.

## MuJoCo scene contract

The `--xml` scene handed to `dora-openarm-mujoco` must provide:

1. The OpenArm v2 bimanual arms (16 position actuators, order
   `left_joint1..7, left_finger1, right_joint1..7, right_finger1`).
2. An `arm_origin` site (teleop reference frame).
3. A `home` keyframe with `qpos` (arms + objects) and `ctrl` (arms) so the
   viewer can reset to a known, stable start state.

`dental_extraction_scene.xml` satisfies all three:
`nq=88` (18 arm qpos + 10 freejoint instruments × 7), `nu=16`, `home` keyframe
generated by `tools/build_scene.py`, instruments resting on the tray.

## What is validated in-repo (no hardware)

- `python -m dental_vla.scene_check` — scene loads, `home` keyframe present,
  `arm_origin` present, 16 actuators, instruments stable on the tray after 1 s.
- Mock packets pass through the **real** `QuestPoseProcessor` and yield finite
  7D poses in the `arm_origin` frame.

Not validated in-repo (needs the dora runtime / GPU / VR): live IK tracking
quality, MuJoCo viewer window, and Quest 3 connectivity. Run section A/B of the
README on a workstation for those.
